# 发布操作规范

版本数字和唯一来源见 [版本管理规范](版本管理规范.md)；日常提交、PR 和并发协作见 [提交与协作规范](../CONTRIBUTING.md)。本文负责从发行准备到可下载产物的完整流程。

## 状态与责任

| 状态 | 完成条件 |
|---|---|
| 代码已提交 | 提交在远程分支；PR 未合并时不能称为已进入 main |
| 已打包 | 对应源码成功生成可交付 JAR，记录来源、版本和哈希 |
| 已打标签 | `v<mod_version>` 固定指向发布源码提交并已推送 |
| Release 草稿 | 说明、兼容性和附件已整理，尚未公开 |
| 已公开发行 | GitHub Release 可见，用户可下载匹配平台的附件 |

打包、标签、公开发行和服务器验收分别报告。发布负责人由维护者确定；协作者默认准备发行材料与草稿。用户明确要求正式发布后即可按授权完成公开发布，无需重复请求已给出的授权。

## 发行准备

1. 抓取远程更新，确认纳入的 PR、源提交和工作区。多名协作者在进行任务时，由同一发布负责人协调本次版本号，不在多个分支各自占用同一版本。
2. 按版本规范更新 `gradle.properties`、`CHANGELOG.md`、部署产物说明、问题记录和真实兼容矩阵。仅文档变更不递增 Mod 版本。
3. 将变更提交并按协作流程进入 `main`；用户已明确授权的直接提交也应保留可审查差异。
4. 为每个拟交付平台执行适用自测、编译和实际运行验证，保留命令、工具版本、结果与待验证部分。当前平台可执行：

   ```bash
   gradle selfTest --no-daemon --console=plain
   gradle clean jar --no-daemon --console=plain
   ```

   `jar` 完成后应确认 Forge `reobfJar` 成功。从干净源码生成产物，不能从 `build/libs/` 里挑旧包发布；环境准备见 [Codex 协作指南](Codex协作指南.md)。未来新增平台应为每个平台补充独立构建命令。
5. 检查 JAR 的文件名、`META-INF/mods.toml` 与 manifest 版本，以及平台元数据。记录文件大小、SHA-256 和完整源提交号。哈希在全部处理完成后计算，上传后不能再修改 JAR。

PowerShell 可使用以下命令，替换尖括号内容后执行：

```powershell
Get-Item 'build/libs/yzt_super-<版本>.jar'
Get-FileHash 'build/libs/yzt_super-<版本>.jar' -Algorithm SHA256
git rev-parse HEAD
git status --short
```

macOS/Linux 可用系统提供的 `sha256sum` 或 `shasum -a 256`。多平台构建最终应使用包含 Mod 版本、Minecraft 版本和加载器的唯一产物名；当前仍按现有构建脚本生成 `yzt_super-<版本>.jar`，命名迁移由适配方案统一实施。

## 标签与 Release

用附注标签 `v<mod_version>` 标记确定的源码提交，先核对该名字是否已经存在。以下为操作模板，替换所有尖括号后执行：

```bash
git tag -a v<版本> <完整源码提交号> -m "野粽乡超级工具箱 v<版本>"
git push origin v<版本>
```

若标签已经存在，核对其指向；只允许补充来源一致且缺失的 Release 材料，不移动标签或用不同来源覆盖同名附件。代码需要修正时走新版本。

按 [发布说明模板](templates/发布说明模板.md) 准备实际说明文件、最终 JAR 和校验文件。使用 GitHub 页面或 CLI 创建草稿；CLI 示例：

```bash
gh release create v<版本> build/libs/yzt_super-<版本>.jar <校验文件路径> --repo BrainLeech198/mc_mod.yezong_town_super_toolkit --verify-tag --draft --title "野粽乡超级工具箱 v<版本>" --notes-file <发布说明路径>
```

源码自动归档不替代 Mod JAR 附件。材料准备完成后核对发行目标和用户授权，发布草稿；预发布版本需明确标识，不能将其作为稳定支持承诺。

```bash
gh release edit v<版本> --repo BrainLeech198/mc_mod.yezong_town_super_toolkit --draft=false
gh release view v<版本> --repo BrainLeech198/mc_mod.yezong_town_super_toolkit
```

## 发布后与回滚

- 核对公开 Release 页面、标签源提交、下载文件名和附件校验值，报告发行链接及未验证项。文档入口与当前产物说明应一致。
- 发现错误产物时停止建议用户升级，在发行说明标明影响，保留可追踪记录并发布修正版。不要悄悄复用同一版本或改写标签。
- 服务器升级前备份世界、配置及数据；回退 JAR 不能恢复已改变的数据格式。数据回滚依照本次迁移说明恢复兼容备份，避免新旧服务器同时写同一份库。
- 更新 [交接说明](交接说明.md) 的发布状态。不能把“已推送标签”报告成“用户已经可以下载”。
