# 写盘故障后的认证状态与菜单生命周期

2026-11-19。基线为 Minecraft 1.20.1、Forge 47.4.0、Java 17、Mod 1.3.4（`53ed590`）。本记录对应多平台适配工作分支。

## 写盘失败时玩家看到什么

基线的 `AuthManager.login` 更新错密次数、锁定期限、上次登录地址或旧密码哈希后忽略保存结果。正确密码可能在更新未落盘时得到成功提示并解锁。下线位置先更新内存，风险面板发生写入异常后还会显示“已处理”。风险库满时追加失败、实际执行旧账号迁移失败、保存留言时清理过期条目，也可能改变本次进程看到的数据。

玩家用旧账号登录时，现在先在账号副本上计算验证结果，保存成功后才允许认证会话解锁、发送欢迎消息和通知管理员。写入失败会报告存储错误，保留原有哈希、计数、锁定期限及登录时间。错密锁定和旧哈希升级共用这一提交顺序。下线快照、风险记录、迁移、留言删除/清理及称号归属各自处理失败回滚。风险记录写盘失败会记入服务端日志；已完成的踢人等游戏操作有独立结果。

五个 JSON 库沿用原有字段、文件名及滚动备份。某个库加载失败后，它会拒绝后续写盘并保全原文件和现有备份。服主可停服，用副本检查损坏原因，恢复有效文件后重启。单条损坏留言仍按条隔离，其余有效留言仍可读取。此变更无需迁移玩家数据。

## 会话和界面

裸认证命令和带前缀的命令现在会在共用登录/注册入口检查通行闸门。未认证连接超时后持续受限，直至退出回调清理状态。留服登出会关闭旧菜单、使该玩家的旧输入动作失效，并同步受限能力和背包。成功认证时按当前原版游戏模式恢复能力，再按配置恢复上次游戏模式。创造、旁观与冒险模式均需要服内验证。

首次铁砧及菜单动作由服务端 tick 驱动。队列中的动作关联玩家实例和实际菜单，执行前检查连接、菜单及玩家是否仍然有效。离服或留服登出会清空该玩家的队列。聊天中的输入方式按钮也限定为原玩家的一次性动作。

## 复现与检查

1. 在独立测试目录使用合成数据创建五库。先让一次写入成功并保存对照。随后在相应库旁新建名为 `<库文件名>.tmp` 的空目录，让实际文件写入返回 I/O 异常。
2. 依次进行登录、错密达到锁定阈值、注册、修改闸门、迁移或其他数据操作。比较玩家提示、Store 中的值和重新加载后的记录。故障期间应保留原值，玩家仍受限。移除该测试空目录后重试，再重启比较。
3. 另备一份合成库及其 `.bak`，用语法损坏的测试 JSON 启动加载，再尝试保存。核对原文件和备份内容，修复测试文件后重新加载并保存。对留言另测单条字段损坏、历史名字大小写及已过期条目。
4. 正式自测入口为仓库根目录的 `gradlew.bat selfTest --no-daemon`（Windows）或 `./gradlew selfTest --no-daemon`。故障注入及重启回读的断言见 [StoreFailureChecks](../../src/selftest/java/com/yztc/auth/selftest/StoreFailureChecks.java)。已有命令、权限、铁砧及原版客户端验收步骤见[部署说明](../../DEPLOY.md)。

开发阶段在 Java 17 和 Gson 2.10.1 上直接编译了文件存储与账号、位置、风险、称号数据类，21 项 I/O 故障、恢复及重读断言通过。随后用已编译的 1.20.1 共享游戏类和 Forge 47.4.0 的默认配置，在 Java 17 上单独执行上述 `StoreFailureChecks`，63 项通过，0 项失败。两次检查均使用临时数据目录。

完整 Forge 自测首轮另发现三条历史 UI 断言仍按旧文案或旧按钮数检查。按 1.3.3 老玩家登录指引和 1.3.0 已增加的大厅按钮更新期望，并检查按钮的实际命令。Forge 47.4.0 最终 `selfTest` 共 1,482 项通过、0 项失败，构建通过。独立服务端启动及原版客户端验收状态见[实施交接](../交接说明.md)。
