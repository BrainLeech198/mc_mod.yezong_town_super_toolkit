# [适配入口已实现] 代理转发地址需可信适配器

- 影响：反向代理后的客户端 IP 识别、登录/闸门 IP 限流、审计和 IP 变更提醒。
- 前置条件：服务器位于代理后，且运维将 `ipResolution` 配为 `auto` 或 `header`。
- 复现步骤：经代理连接并启用 `header`；当前 `HeaderProbe.firstValue` 恒返回 `null`，随后地址解析回退到代理连接地址。
- 预期结果：通过受信任的服务端集成取得经过验证的客户端地址；无集成时回退到连接地址。
- 实际结果（修复前）：`HeaderProbe.firstValue` 恒返回 `null`，`forwardedHeaderName` 看似可配置但没有读取入口。
- 根因/调用链：Minecraft TCP 协议不提供通用 HTTP 转发头；不同代理使用不同握手/登录协议，Forge 需由相应适配器接入。
- 修复范围：新增 `ClientIpResolveEvent` 通用扩展点；`auto` 优先采用首个可信监听器设置的地址，再回退连接地址；`remote` 强制直连地址；`header` 保留为兼容别名。未内置猜测/信任任意代理协议。
- 验证：静态检查解析顺序、事件默认回退和配置说明；`gradle jar --no-daemon` 编译与重映射成功；未在具体代理适配器上联调。
- 状态：适配入口已实现；具体代理适配器按部署环境提供
- 修复版本：`1.1.0`
