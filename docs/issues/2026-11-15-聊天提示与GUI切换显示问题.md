# [已修复] 聊天提示与 GUI 切换显示问题

- 影响：从账户、写信等箱式 GUI 进入聊天提示/输入方式选择时，旧菜单仍可能留在屏幕上；输入方式按钮的装饰括号重复，聊天框宽度还会受客户端语言影响。
- 前置条件：从箱式菜单点击会发聊天提示的功能，或客户端语言与服务端兜底语言不同。
- 复现步骤：账户面板点登出，或写信面板选择玩家；观察聊天栏提示出现时的菜单状态与输入方式外框。
- 预期结果：先关闭旧菜单再显示聊天提示；两个入口各只有一层括号，外框能容纳中英文客户端文本。
- 实际结果（修复前）：聊天提示与旧箱式菜单短暂/同时显示；按钮显示双层括号，框宽按服务器侧解析出的文字测量，可能与客户端实际文案宽度不一致。
- 根因/调用链：`ButtonPanel.Menu.clicked` 延后执行动作但在动作后才关菜单；`MailPanel.ComposeMenu` 的 `InputPrompt.choose` 只发聊天文本；`ChatPrompt` 包含括号而按钮翻译自身也带括号；`ChatBox.box` 使用服务端 `Component.getString()` 计算客户端本地化文本宽度。
- 修复范围：按钮面板先关旧菜单再执行动作；聊天输入提示和登出提示也确保关闭当前菜单；按钮翻译改为无装饰纯标签；输入方式框按中英文较宽布局留空间。
- 验证：`gradle jar --no-daemon` 编译与重映射成功；JSON 解析通过；未运行自测或游戏内跨语言验收。
- 状态：已修复
- 修复版本：`1.1.2`
