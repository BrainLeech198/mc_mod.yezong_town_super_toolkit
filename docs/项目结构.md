# 项目结构与运行链路

## 项目概况

`yzt_super` 是面向 Minecraft 1.20.1 的 Java 17 服务端 mod。根构建交付 Forge，`platforms/fabric-1.20.1/` 独立构建 Fabric。两者使用同一份 official mappings 版的玩家、命令、菜单和存储实现，`common/` 提供不依赖游戏的密码哈希、限流与字宽逻辑。当前仓库使用 Gradle；主代码位于 `src/main/java/com/yztc/auth/`，纯逻辑自测器位于 `src/selftest/java/`，资源与中英文语言文件位于 `src/main/resources/`。

## 模块职责

| 包/位置 | 职责 | 代表入口 |
|---|---|---|
| `YzAuthMod` | Forge 装配、注册配置、创建并共享服务/存储对象 | mod 构造器 |
| `auth` | 登录、注册、闸门、限流、玩家认证状态 | `AuthManager`、`GateManager`、`AuthEvents` |
| `lockdown` | 未认证状态的事件拦截、位置回退和客户端状态同步 | `LockdownHandler`、`LockdownSync` |
| `command` | Brigadier 命令注册与管理操作 | `RootCommand`、`AdminCommands` |
| `data`、`security` | JSON 持久化、账号/留言/风险/位置数据和密码哈希 | 各 `*Store`、`PasswordHasher` |
| `ui` | 原版可见的服务端 GUI、输入流程、聊天提示 | `HomePanel`、`AuthGui`、`InputPrompt`、各面板 |
| `config`、`lang` | 两端共用的配置定义与中英文文案 | `AuthConfig`、`Lang`、`ServerLang` |
| `broadcast`、`title`、`audit`、`risk`、`perm` | 广播/挂机、称号、审计、高风险记录与权限适配 | 对应包内 service/command/event |

## 平台入口

Forge 从 `YzAuthMod` 注册配置、认证和称号事件。Fabric 从 `FabricToolkit` 注册同一配置定义、`FabricEvents` 和服务端 Mixin。Fabric 在 dedicated server 入口装配服务，在 `SERVER_STARTING` 绑定世界配置、`SERVER_STARTED` 加载依赖配置的库。两端通过 `ToolkitServices` 装配相同的库和服务，通过 `PlayerLifecycle` 处理进服、就绪、退出。Fabric 在 `PlayerList.placeNewPlayer` 结尾触发进服，在 `remove` 开头记录下线。命令注册与执行前拒绝分开；`LockdownRules` 共用允许的入口、tick 和菜单延迟队列。每个加载器的地址适配见[代理契约](代理IP适配.md)，运行证据见[平台验收](平台验收.md)。

## 生命周期和主要调用链

### Forge 启动

1. Forge 创建 `YzAuthMod`。
2. 注册 SERVER 配置，加载账号库，并创建其他存储对象。
3. 创建 `GateManager`、`AuthManager`，绑定共享引用并注册事件处理器。
4. `ServerStartedEvent` 加载依赖服务器配置的数据文件，打印启动横幅。
5. `RegisterCommandsEvent` 注册 `/yzts` 与裸 `/login`、`/register`。

### 玩家登录

```text
PlayerLoggedInEvent
  -> AuthEvents.onLogin
  -> PlayerLifecycle.joined
  -> AuthManager.onJoin
      -> 创建 PendingState
      -> 选择闸门提示或登录/注册提示
      -> 排队打开 AuthGui
      -> 隐藏未认证玩家的 Tab 项
  -> LockdownSync.lock

每 tick:
  -> Forge LockdownHandler.onTick / Fabric END_SERVER_TICK
  -> LockdownRules.tick
      -> AuthManager.onTick（超时、标题重发）
      -> 未认证位置回退
      -> 锁定期间的命令/交互/聊天拦截
```

### 密码提交

GUI 输入流程和命令最终都进入 `RootCommand.doGate`、`doLogin` 或 `doRegister`，再调用 `AuthManager` / `GateManager`。账号查找使用小写玩家名；成功后更新认证状态、持久化账号数据并调用 `LockdownSync.authenticate`，随后按 `restoreLastGameMode` 配置恢复 `lastseen.json` 中记录的游戏模式。修改认证结果时应同时检查 GUI 入口、命令入口和锁定状态迁移。

### 铁砧输入

`AnvilInput` 用左侧占位纸承载原版重命名文本，右侧结果槽作为明确的「提交」按钮；Esc/关窗只取消。单步调用仍通过 `UiSession` 完成一次性回调。改密、邮箱改绑、管理员重置密码和手输收件人写信使用 `openFlow`：每步返回关闭、当前步骤重试或进入下一步，输入清空后沿用同一个菜单；后续步骤提示发到聊天栏。新接入多步骤输入时，应把验证和状态变更写在各自步骤处理器中，取消逻辑保持无副作用。

### 功能大厅

`/yzts` 与 `/yzts menu` 进入 `HomePanel`；面板复用既有服务入口，并按账户/留言、小镇工具和管理员区分区。登录成功聊天提示也提供大厅入口。增加大厅按钮时维护中英文键、权限可见性与已有命令/面板调用。

## 边界与数据落点

- 业务代码统一通过 `AuthConfig` 访问世界配置。Forge 注册原生 SERVER 配置，Fabric 的 `FabricWorldConfig` 绑定实际世界目录，在服务端线程检查热更新；两端读取同名 TOML。
- 账号、留言、最后位置/游戏模式、风险记录和称号数据分别由对应 Store 读写；主要落点为 `config/yzt_super/*.json`。`lastseen.json` v1 没有模式字段时按缺省值读取，不恢复模式；升级保存后写为 v2。
- 审计日志位于 `logs/yzt_super-audit.log`。敏感认证材料不得写入日志或风险记录。
- 认证用远端地址从 `InetSocketAddress` 提取主机部分，不包含每次连接变化的客户端临时端口；这个值共用于登录/闸门限流、审计和 IP 变更提醒。
- `ipResolution=auto` 会同步发布 `api.ClientIpResolveEvent`。可信的服务端代理适配 mod 可在验证转发来源后设置 `InetAddress`；首个设置者生效。无人提供时回退连接地址。`remote` 不发布事件并强制使用连接地址；旧 `header` 值作为 `auto` 别名保留。适配器必须验证自身代理协议/来源，不能直接信任玩家可控字段。
- `DEPLOY.md` 是当前部署和运维操作的主说明；本文件只维护代码结构与调用链，不复制整套命令/配置表。

## 变更时的维护点

- 认证状态或进服行为：核对 `AuthManager`、`AuthEvents`、`LockdownHandler`、`AuthGui` 和相应命令入口。
- 铁砧输入行为：核对 `AnvilInput` 的结果槽点击、Esc 取消与菜单生命周期，并核对各 `openFlow` 步骤是否在失败时留在正确步骤。
- 持久化：核对 Store 的加载/保存、损坏文件处理、备份与调用方错误提示。
- 配置或命令改变：同步维护 `DEPLOY.md`。
- 发现缺陷：按 [文档编写规范](文档规范.md) 留下可追踪的复现、根因、影响和验证结果。
