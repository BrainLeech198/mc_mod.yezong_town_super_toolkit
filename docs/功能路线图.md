# 主流 Mod 功能对照与整合路线图

本文按公开文档盘点可借鉴的产品能力，不复制其他项目的实现代码。兼容目标仍是 Minecraft 1.20.1 / Forge 47 / Java 17；Paper 插件或 Fabric/NeoForge Mod 的 API 不能直接当作 Forge 实现依赖。

## 现有能力

- 登录/注册、全服密码闸门、失败限流与锁定、未认证隔离、账号密码迁移。
- 邮箱绑定、私信与公开留言、称号、公告/喊话、最后下线位置与模式恢复。
- 管理员账号面板、危险操作记录、代理来源地址适配。

## 可借鉴的主流方向

| 参考项目 | 公开能力 | 对本项目的启发 | 兼容边界 |
|---|---|---|---|
| [AuthMe Reloaded](https://github.com/AuthMe/AuthMeReloaded) | 登录会话、邮件找回、反机器人、代理协作、可配置命令、语言和数据库/迁移 | 账户找回、经过身份校验的跨服会话、数据备份与导入 | Bukkit/Paper 插件，不能直接装到 Forge；其新图形登录框要求更高版本 Paper/Spigot，不适用于当前 1.20.1 Forge |
| [EasyAuth](https://github.com/NikitaCartes/EasyAuth) | 服务端认证隔离、IP/会话限制、2FA、数据库后端、服务器端翻译 | 认证状态隔离和多后端适配的功能边界 | 上游面向 Fabric/NeoForge；只借鉴需求和交互，不复用平台专属代码 |
| [FTB Essentials 文档](https://docs.feed-the-beast.com/mod-docs/mods/suite/Essentials/Commands) | 家、传送请求、返回、出生点、随机传送、公共传送点 | 把账号工具箱扩展为玩家日常服务器工具 | 可按 Forge 47 API 独立实现；要考虑其他 Mod 的命令冲突、权限与目的地安全 |

## 分阶段建议

### 1. 新手认证体验（当前批次）

- 首次进入明确写“设置密码”；老玩家明确写“输入之前的密码”。
- 告诉玩家铁砧顶部输入、右侧绿色提交、Esc 关闭分别做什么。
- 失败后保留窗口并给下一步；注册成功只保留简单的密码记忆/保密提示。
- 自动区分登录与注册，避免要求孩子自己理解两套指令。

### 2. 玩家常用传送工具

- 优先评估 `/sethome`、`/home`、`/back`、`/spawn`。
- 后续再评估 `/tpa` 请求/接受/拒绝与 `/warp`；请求应有过期、撤回和传送安全检查。
- 每个新功能单独设置权限节点与配置开关；命令冲突时保留 `/yzts` 命名空间入口。

### 3. 账号与数据可靠性

- 邮箱找回需要可用的邮件服务、验证码过期/限流、变更确认和防滥用机制；仅存邮箱地址并不等于可以安全找回密码。
- 会话免密不能只凭用户名；离线服的玩家名可被冒用。只有代理提供经过验证的身份并使用签名/共享密钥时，才评估跨服免密，默认关闭。
- 继续统一检查 JSON 写入、失败回滚、备份恢复和升级兼容；将来可加 SQLite 适配器，但 JSON 继续作为零依赖默认后端。

### 4. 管理与兼容

- 参考 FTB Essentials 的做法：新命令可单独禁用，权限说明明确，避免和服务器已有指令抢名字。
- 代理、权限、存储和邮件集成采用可选适配器；默认环境未知时不假定特定代理、邮件服务或数据库存在。
- 每批只实现一个可独立构建/验收的功能组，补充命令说明、配置默认值、风险边界和可复现缺陷记录。

## 当前实施状态

- 认证文案与失败重试指引：已在 `1.3.3` 完成并打包；变更说明以根目录 `CHANGELOG.md` 为准。
- `/home`、`/back`、`/spawn`、`/tpa`、`/warp`：候选功能，尚未承诺具体命令冲突策略、家数量和权限默认值。
- 邮件找回、会话免密、数据库后端：需先完成身份、外部服务和迁移边界设计，默认不启用。
